# Plan: Bobbing mines

**Status:** done (commits `c37e90b`..`f7b8d54`; per-mine local tick added in `215938f`).

Passive hazard that floats in place, oscillating on a sine wave around its authored position. There are two types, vertical and horizontal. Bullets destroy a mine (explosion and score); touching one destroys both the mine and the ship. Each instance has its own phase and amplitude, so a group does not move in lockstep.

SWRAM-only behind `_BOBBING_MINES` (`thrust.6502:42`); the non-SWRAM CRC `6389c446` is unaffected.

## 1. Object types and per-type tables

```
OBJECT_bobbing_mine                 = $E        ; vertical bob   (thrust.6502:130)
OBJECT_bobbing_mine_horizontal      = $F        ; horizontal bob (thrust.6502:131)
```

Both types have the same entries in the per-type tables, inside `IF _BOBBING_MINES`:

| Table | Value | Line |
|-------|-------|------|
| `obj_type_width` | `$03` (chars) | `thrust.6502:1437` |
| `obj_type_height` | `$0C` | `thrust.6502:1453` |
| `obj_type_explosion_particle` | `$02` | `thrust.6502:1470` |
| `obj_type_score_value` | `$50` | `thrust.6502:1487` |
| `object_type_cull_size_table` | `$44` | `thrust.6502:2353` |

The sprites `obj_sprite_data_A/B_bobbing_mine` and `..._horizontal` (currently the same graphic) live in `tools/output/object_sprites.asm`, generated by `tools/sprite_editor.py`, and are plotted by the normal static-sprite path.

## 2. Per-instance data layout

Uses the generic `level_N_obj_data_0..2` slots; no mine-specific arrays.

| Slot | Field |
|------|-------|
| `obj_data_0` | Phase, 0..255: starting index into the 256-entry sine table |
| `obj_data_1` | Amplitude, signed: peak offset in world units (Y units for vertical, X units/chars for horizontal) |
| `obj_data_2` | Runtime state: the offset applied last frame. Exported as 0. |

The routine moves the mine by writing directly into the level's position arrays (`level_N_obj_pos_Y` / `_Y_EXT` for vertical, `level_N_obj_pos_X` for horizontal). Each frame it applies `new_offset − prev_offset` as a delta and stores `new_offset` in slot 2, so the stored position is always `authored position + slot 2` and no restore is needed when the level restarts.

`bobbing_mine_local_tick` (`thrust.6502:13475`, 32 bytes indexed by object slot) is the per-mine time counter. `initialise_level_pointers` zeroes it and patches the mine SMC sites (`thrust.6502:7379` onward).

## 3. Per-frame update

`update_and_draw_all_objects` calls `update_bobbing_mine` (`thrust.6502:13541`) or `update_bobbing_mine_horizontal` (`thrust.6502:13637`) by type, before `object_visibility_test` reads the position (`thrust.6502:1681-1697`).

```
if OBJ_flag_disabled: return                      ; frozen in place, tick not advanced
idx        = (phase + bobbing_mine_local_tick[X]) AND $FF
new_offset = hi(2 * amp * bobbing_mine_sin_table[idx])   ; multiply_signed_8x8, then ASL/ROL
delta      = new_offset - slot2[X]
vertical:    level_obj_pos_Y/_EXT += sign_extend(delta)   ; 16-bit
horizontal:  level_obj_pos_X      += delta               ; 8-bit, wraps
slot2[X]   = new_offset
bobbing_mine_local_tick[X] += 1
```

`bobbing_mine_sin_table` holds `sin(2π·i/256)` as signed Q0.7, with −128 clamped to −127 so the signed multiply stays well-behaved. One full cycle is 256 game frames, about 7.8 seconds at ~33Hz. The peak-to-peak travel is `2·|amp|`; a negative amplitude reverses the starting direction.

Using a per-mine tick rather than `level_tick_counter` means a mine frozen by `OBJ_flag_disabled` resumes from where it stopped.

Cost: one `multiply_signed_8x8` (~220-380 cycles) plus about 80 cycles of loads and adds, so roughly 400 cycles per mine per frame. Because the position changes every frame, the mine is erased and redrawn every frame by the normal XOR sprite path.

## 4. Collision

- **Bullets:** `check_generic_destructible` (`thrust.6502:2043`) sends `$0E` and `$0F` to `destroy_object`, which clears `OBJ_flag_alive`, spawns the explosion and awards the score.
- **Ship:** an explicit bounding-box test before the planet-explode trigger (`thrust.6502:1837-1896`) rather than relying on ship-vs-pixel collision, which could lag the moving mine by a frame. Contact is `|mine_y − player_y| < 11` (world Y, 16-bit) and `|mine_x − player_x| < 5` chars. On contact it sets `plot_ship_collision_detected = $FF` (ship dies) and jumps to `destroy_object` (mine explodes). With `_SWITCHES`, a disabled mine skips this test, but can still be shot.

## 5. Editor support (`tools/level_editor.py`)

- Constants: `OBJECT_BOBBING_MINE = 0x0E`, `OBJECT_BOBBING_MINE_HORIZONTAL = 0x0F`; new mines default to `BOBBING_MINE_DEFAULT_PHASE = 0`, `BOBBING_MINE_DEFAULT_AMP = 32`.
- Fields `mine_phase`, `mine_amp` on the object dict, exported to slots 0 and 1, with slot 2 written as 0. Import reads them back from the `obj_data` arrays.
- Keys with a mine selected:
  - `[` / `]`: amplitude −1 / +1 (Shift = ±10), clamped −127..+127
  - `,` / `.`: phase −1 / +1 (Shift = ±8), wrapping 0..255
- Both are also editable in the properties panel (`SCHEMA_BOBBING_MINE`).
- `_render_bobbing_mine_amp_bar` overlays a bar showing the travel range: vertical for `$0E`, horizontal for `$0F`.

## 6. Notes

- The original plan reserved slot 2 for a blast-radius byte. It is used for the previous-offset state instead; the mine just uses the standard explosion.
- The routine runs for every mine in the list each frame, whether or not it is alive or on screen. A destroyed mine keeps updating its (undrawn) position, which is harmless.
- The header comment above `bobbing_mine_sin_table` in `thrust.6502` still describes indexing by `vsync_count` masked to `ANGLE_MASK`; the code uses `bobbing_mine_local_tick` and the full 256-entry table.
